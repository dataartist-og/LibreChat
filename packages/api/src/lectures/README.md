# Lecture study backend

Authenticated routes:

- `POST /api/lectures/youtube`: `{videoUrl}` retrieves public video title/description and a timestamped caption track, preferring manual English, automatic English, then another available language. It returns `{title,videoUrl,description,transcript,transcriptKind,language,sourceUrls,warnings}`. If metadata succeeds but captions are disabled, refused, rate-limited, or unusable, metadata and links still return with `transcript: ""`, `transcriptKind: "unavailable"`, and a manual-transcript warning. This supports attempts for arbitrary individual YouTube video URLs; it cannot guarantee captions for every video.
- `POST /api/lectures/source`: `{source: {id,title,url}}` returns sanitized article HTML, resolved URL, and title.
- `POST /api/lectures/ask`: `{lecture,momentId,question,sourceId?,history?,focus?:{sourceId,anchor}}` returns `{answer,citations,takeaways?}`. A selected `sourceId` explores that source independently of the moment's evidence mapping. Optional `focus` prioritizes an actual passage while retrieval also searches the rest of the selected source for relevant evidence. If both are provided, their source IDs must match. Unknown sources or focus anchors are refused. Authored moment notes are excluded from source exploration; ordinary moment tutoring includes them only as untrusted navigation context. The model writes a direct conversational answer, normally under 250 words, and optionally 1–3 factual takeaways established in that answer (300 characters each). Citation links are generated only from verified, retrieved passages; model-supplied links or unknown keys are rejected.
- `POST /api/lectures/notes`: `{lecture,momentId,question,answer,sourceId?,focus?}` returns `{takeaways}`. This extracts up to three source-supported factual insights from a completed conversation, without inferring learner mastery. It returns an empty array when no supported insight was established. Questions are capped at 4,000 characters and answers at 18,000; extraction retrieves source evidence again and verifies internal citation keys. Typed tutoring already returns takeaways, so it does not require an additional extraction call.
- `POST /api/lectures/index`: `{title,videoUrl,transcript,description}` returns a validated lecture manifest. Transcript timestamps must start lines in `MM:SS` or `HH:MM:SS` form. The last playback boundary is estimated from the final passage.
- `POST /api/lectures/import`: a lecture manifest returns the validated lecture without network/model calls. Moment intervals must be chronological and nonoverlapping; leading gaps are allowed.

Text tutoring, indexing, and notes extraction use the installed Codex subscription adapter by default. There is no automatic paid API fallback. Explicitly setting `LECTURE_MODEL_PROVIDER=openai` enables the existing server `OPENAI_API_KEY` and official/proxy transport; that opt-in may incur API charges. In this opt-in mode model precedence is `STUDY_MODEL`, `INLINE_CLARIFICATION_MODEL`, then `OPENAI_MODEL`; otherwise a compatible configured proxy model is selected, or `gpt-4o-mini` for the official endpoint. It does not inherit the chat model selector. API tutor output is capped at 4,000 completion tokens, notes at 1,200, and indexing at 16,000. API requests time out after 90 seconds and do not retry automatically.

Sources must expose public HTML. Modern arXiv abstract/PDF URLs are canonicalized to HTML; other PDFs are not ingested by these routes. There is no autonomous independent search: indexing reads the supplied description URLs. Retrieval is not proof that a page is authoritative; the user supplies its research sources. Unsupported or failed sources are reported and excluded from evidence. A moment without mapped evidence can still explore a selected source; grounding requires relevant retrieved passages.

Question retrieval scans extracted passages across the source using lexical BM25 ranking, query expansions, and heading matches. Questions about data, setup, and outcomes prioritize matching dataset, method, result/table, and limitation sections. Focused passages come first. Retrieval includes at most 16 passages per source, 20,000 passage-text characters overall, and 30,000 serialized context characters. Each extracted source block retains at most 5,000 characters; this is bounded lexical retrieval, not exhaustive full-paper comprehension or semantic entailment verification. An unmatched specific question can return no evidence. The shared `buildLectureContext` helper exposes the same bounded real-source context to voice sessions. Model factual support still depends on the quality of the retrieved evidence and the model's interpretation; server validation verifies identities, anchors, output bounds, and citation links.

Retrieval checks public URLs and DNS targets on every redirect, uses the repository's protected connection agents with IPv4 hostname lookup, follows at most four redirects, and caps each HTML response at 4 MB and 15 seconds. No source cookies or authorization headers are forwarded. A bounded in-memory cache retains up to 24 successful sources / 32 MB for 30 minutes. Description input supports up to 24 source URLs, retrieved in batches of four. Transcripts are capped at 160,000 characters. Conversation history is capped at 12 messages of 6,000 characters; questions at 4,000 characters.

The source reader preserves article structure, original anchors, MathML, static SVG, captions, tables, and public figure image URLs. Anchorless paragraphs receive stable reader-only identifiers; citations for them link to the publisher page without a nonexistent fragment. Original publisher anchors retain external deep links. It strips scripts, event handlers, forms, embeds, styles, and unsafe URLs. Public figure images load in the frontend reader with no referrer. The frontend must retain its independent sanitizer and restrictive sandbox/CSP. API errors are JSON `{error:string}` with 400 validation, 404 unknown moment, 422 unavailable source/evidence, 502 invalid model response, or 503 missing model configuration.

Run targeted checks from `packages/api`: `npx jest src/lectures --runInBand --coverage=false`.

YouTube metadata import requires `python3 -m yt_dlp` on the server; `LECTURE_PYTHON` can name another Python executable, or `LECTURE_YTDLP_PATH` can name an installed yt-dlp executable. It runs without a shell, ignores configuration/plugin directories, requests one video's metadata only, and explicitly skips media downloads. No browser cookies, account authentication, local credential configuration, or CAPTCHA/sign-in bypass is used. The subprocess receives only basic runtime environment variables, has a 45-second timeout and 4 MB output cap. Caption fetching uses protected DNS connection agents, a 15-second timeout, a 4 MB limit, at most two redirects, and only HTTPS YouTube timed-text paths. Only public User-Agent/Referer headers are forwarded. Captions are normalized from JSON3 or VTT to the existing indexer's timestamp format, with a 160,000-character limit. Current live checks retrieved public metadata for two videos; caption requests returned HTTP 429, so the working metadata/manual-transcript fallback must not be described as a verified automatic-caption success. The metadata/caption-only flags follow the [official yt-dlp options](https://github.com/yt-dlp/yt-dlp#usage-and-options).

## Native subscription conversation

`GET /api/lectures/voice` reports `{available,reason?,provider:"codex"}` from the installed Codex process and its existing managed ChatGPT login. This checks local setup, not guaranteed upstream voice entitlement. `POST /api/lectures/voice` accepts `{lecture,momentId,sourceId,focus?,sdp}` and returns `{sessionId,sdp}` after native WebRTC negotiation. `POST /api/lectures/voice/stop` accepts `{sessionId}`. Sessions belong to the authenticated LibreChat user, allow one active conversation per user, and expire after 15 minutes. A new conversation replaces the user's previous one. Stop, cancellation, native disconnect, and expiry clean up the child process.

The default executable is discovered in the installed ChatGPT/Codex macOS app or standard Codex binary locations; `LECTURE_CODEX_BINARY` can specify another absolute path. `LECTURE_CODEX_MODEL` optionally selects the backing text model. The adapter was verified against Codex **0.153.4** using its generated experimental protocol. It uses private stdio RPC, managed ChatGPT authentication and WebRTC **V3**, with no login changes, token export, or Platform API-key fallback. The child environment excludes API keys and proxy credentials. Custom OpenAI-provider or realtime URL overrides are refused. Subscription limits still apply; a compatible installed version and upstream voice entitlement are required.

The browser creates an audio `RTCPeerConnection` and an `oai-events` data channel. Native V3 uses `input_transcript.added`, `output_transcript.added`, and `turn.done` (`turn.role`, `turn.transcript`); these differ from the standard Platform Realtime protocol. Audio travels over WebRTC. The source passages selected when the conversation starts provide a fixed, bounded context; the model must acknowledge missing details in follow-up questions. Typed questions retrieve source passages again for each question. Voice takeaways use the separate source-verified notes endpoint after completed exchanges.

Each native tutor thread is ephemeral and starts in a new empty temporary directory with a read-only sandbox, no environments, no dynamic tools or selected capability roots, disabled execution/browser/plugin/app/memory features, and every configured MCP server disabled. The adapter checks that the native MCP inventory exposes no tools before inference, rejects server-initiated tool/approval requests, and caps concurrent child processes at six. Read-only permissions alone are not treated as filesystem isolation: empty environments and tool suppression prevent source text from accessing local files. A live canary-file request confirmed no file access or tool events. The bridge exposes only study operations, never arbitrary native RPC methods.
